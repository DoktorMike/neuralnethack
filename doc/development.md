# Development

Build system details, workflows, and how to extend the library.

## Build system

The Makefile wraps CMake:

```sh
make          # configure + build (Release)
make test     # run all tests
make examples # build the examples target (nnh_examples)
make coverage # build with gcov, run tests, generate HTML report
make format   # apply clang-format to all source files
make single-include # regenerate the amalgamation + smoke-compile
make release  # format + test + amalgamation checks, then standard-version
make clean    # remove build directories
```

Direct CMake works too:

```sh
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

### Build options

- `-DNNH_USE_BLAS=OFF` — disable BLAS (auto-detected otherwise; install
  `libopenblas-dev` or similar for best performance).
- `-DNNH_OPENMP=OFF` — disable OpenMP (auto-detected; used to train ensemble
  members in parallel, controlled at run time via `OMP_NUM_THREADS`).
- `-DNNH_COVERAGE=ON` — instrument for gcov/lcov (used by `make coverage`).

Requires GCC 13+ or Clang 17+ for C++23.

## Single-header amalgamation

The whole library ships as a generated single header at
`single_include/neuralnethack.hh` (stb-style: define `NNH_IMPLEMENTATION` in
exactly one translation unit). It is regenerated by `scripts/amalgamate.py`,
which topo-sorts the public headers by include deps, dedupes system includes,
and gates the implementation under `NNH_IMPLEMENTATION`:

```sh
make single-include   # regenerate + smoke-compile
```

Never edit `single_include/neuralnethack.hh` by hand. CI runs the same target
on every PR and fails if the committed header is out of sync with the source
tree, so regenerate and commit it whenever library source changes.

The amalgamation is self-contained: BLAS and OpenMP are optional, not required
to compile. Consumers opt in with `USE_BLAS` / `NNH_USE_OPENMP` and link the
matching libraries (`-lopenblas` / `-fopenmp`).

## Adding a new activation function

1. Add type string to `MultiLayerPerceptron.hh` (e.g. `#define MYACT "myact"`)
2. Add a tag `struct MyAct {};` to `Activation.hh` and add it to the `Activation` variant
3. Declare the `fire`/`firePrime`/`firePrimePrime` (+ `*FromOutput`) and `applyActivation`/`applyDerivScale` overloads for `MyAct` in `Activation.hh`
4. Implement those overloads in `Activation.cc`, with the math
5. Wire the tag into `activationFromTag` / `activationToTag` in `Activation.cc`
6. No Layer subclass or Mlp change needed: `createLayers()` builds layers via `activationFromTag`, and `std::visit` picks up the new variant alternative automatically

## Releases

Always cut releases with `make release`. It enforces the order: clang-format
applied and committed, all tests green, amalgamation regenerated and
committed, THEN standard-version (bumps CMakeLists.txt via `.versionrc`,
writes CHANGELOG.md, tags). Never run standard-version directly; formatting
must land before the tag, not after.
